# 保存弹窗与隐藏输入校验修复

日期：2026-10-14。基于2.1.2提交0266294，尚未提交或发布。

## 后续调整：训练启动门槛由系统管理

按用户确认，移除首页及保存窗口中的“训练所需最少纳入或排除决定数”输入。有效门槛统一使用现有系统默认5，旧任务文件中保存的手动值不再覆盖它；保存其他机器学习设置时也不提交这一指标。旧API字段保留以兼容旧请求，但不用于改变门槛。训练、特征提取和排序方法保持原有实现。

下文的1–1000输入错误是原问题的复现记录，不代表更新后的填写要求。既有浏览器回归中的可编辑数值案例已调整为“停止建议阈值”；本次没有重新运行该自动化套件。

## 已复现的原因

1. 机器学习输入、流程设置和原因库采用“曾触发输入事件即未保存”的标志，改回原值仍会弹出保存窗口。
2. 首页的机器学习输入可以被切换选项隐藏；保存窗口仍提交这些输入。min_labeled=1001会得到后端422，但窗口中没有输入框供纠正。类似问题影响隐藏的原因库输入。
3. 整个workflow-settings响应被当作策略比较对象，版本、来源计数变化也会触发策略核对提示。已复现仅版本／计数变化、机器学习草稿未保存时显示策略恢复提示。

复现在独立测试任务进行。API错误案例拦截机器学习设置请求，未写入用户数据库。原版运行记录及截图位于本地guard-fix-validation与guard-before.png。

## 修复范围

- 对流程设置、机器学习输入、原因库及来源类型采用保存基线与当前值比较；恢复原值不再保持未保存标志。
- 保存窗口提供实际未保存的流程、机器学习及原因库／来源类型输入，复用现有提交函数；先校验，后提交。
- 数值约束与现有后端一致。空白、小数及超出范围的数值不再被默认值或parseInt静默替代；错误指出字段、范围并聚焦可见输入。新增说明覆盖十种现有语言。
- 放弃机器学习草稿会恢复保存基线；保存期间的新编辑与服务器确认的值比较，避免丢失后续编辑。
- 区分策略内容与版本／来源显示统计。真实权限、阶段来源和证据要求变化继续保护有关草稿，队列版本更新检查继续保留。
- 未修改后端API、匹配算法、数据库或E:/ReviewFlow安装目录。
