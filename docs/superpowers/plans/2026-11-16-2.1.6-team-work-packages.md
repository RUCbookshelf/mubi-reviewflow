# 2.1.6 可派发工作包 Implementation Plan

> **For agentic workers:** 执行时使用已列出的 `subagent-driven-development`，只领取一个包/一个阶段。先读总 DAG、接口合同对应 C 编号，再领取确切依赖交付；本文件不是当前 CODE 派单。

**Goal:** 把已定路线拆成可以独立拒收、修复、复审和运行的单元。

**Architecture:** 基础窄接口并行；按键计划到写窗串行；真实路由按文件 ownership 串行；所有实现汇合后再停笔规范和完整验证。

**Tech Stack:** 现有 Python/SQLite/FastAPI 与 unittest/pytest；g-flash/luna/oc-ds/cc-ds 异构配对。

## Global Constraints

`custom_frontend/` 只读；真实 data/DB/key/8613 不碰；不在主仓跑产品/API/测试；新 scratch + Python3.12.13 `-I -B`；不 git 写入/改版本；不重建索引；旧 raw/箱/存档只读。所有符号先实际 impact，HIGH/CRITICAL 改前向用户报告。完整约束继承总计划，无包能豁免。

## 每包共同步骤与运行方法

- [ ] I：作者和测试作者分别列旧/新符号、实际 upstream impact、当前源码 callers、必要文件及 before SHA，交主控风险通报。符号不在图记录 UNKNOWN，不能先改后补。
- [ ] C：先写下列具名反例/正控，产品最小实现；只在白名单文件 AST/compile，不 import 产品/执行 SQL/probe。保精确 before/after/patch、方法名与 API 签名；每个源码/测试文件只有一名作者。
- [ ] Q：冻结两侧，按总表另开异构产品审；测试用独立 DeepSeek 审，P01 旧 DeepSeek 测试用 Luna 审。规格与质量两项分别 PASS，具体疑问在新 synthetic 箱验证，不改旧失败证据。
- [ ] R：独立执行者生成 RUN_PACKET，先 source/环境/工具审，再在新短 scratch 运行。本文件 `Test:` 路径就是该包 pytest 的精确选择；unittest-compatible 文件先全部 unittest，通过后再 pytest，同样不 skip/deselect。用例数量以冻结 AST/实际收集一致为准。
- [ ] E：异构执行审核原 bytes/status、runtime 源、清理与持久化；主控读完才 ACCEPTED。仅 docs/EOL 包不造无意义业务测试，以精确字节/引用/图检查验收。

单包 child pytest 实际 argv 为 `[PY, '-I', '-B', '-c', BOOTSTRAP, SRC, Test, '-q']`，BOOTSTRAP 精确如下；controller 在启动前设置 cwd=SRC 与隔离 env，并执行验证文档所有来源/清理门：

```python
import sys, runpy
source_root = sys.argv.pop(1)
sys.path.insert(0, source_root)
sys.argv[0] = 'pytest'
runpy.run_module('pytest', run_name='__main__')
```

不能把这段单独从主仓运行，不能只给 exit0 丢掉 RUN_PACKET 证据。直接标准 unittest 的受控 adapter 同样只加入批准 SRC、加载本包全部 TestCase，失败时不继续 pytest。正式整体验证仍只能用原八步入口，不能以本节单包选择替代。
