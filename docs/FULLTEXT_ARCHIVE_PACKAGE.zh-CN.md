# 全文规范归档与任务整包（2.1.5 W5）

> 用户可见功能说明 + 数据安全声明。面向：任务负责人（导出/交接/归档）。

## 一、全文归档导出（只要 PDF）

任务页「全文归档导出」可把任务里的全文打包成一个 zip，每个 PDF 都按
**人话规范名**命名：

```
{文献键}-{第一作者姓氏}-{年份}.pdf
```

- 例：`AB12CD34-Wang-2023.pdf`、`AB12CD34-王-2022.pdf`。
- 缺作者/年份的条目命名为 `...-unknown-unknown.pdf`，**不会被跳过**。
- 文件名会把 Windows/macOS 不允许的字符（`< > : " / \ | ? *`）与控制字符
  替换为 `_`；主干最长 120 字符；规范化后撞名时自动追加短哈希后缀。
- 范围三选一：全部已取全文 / 初筛纳入 / 复筛纳入。纳入口径是**当前生效
  决定**（多筛员冲突且未仲裁的条目不进入纳入范围）。
- 结果摘要显示「成功 N、跳过 M」：登记了全文但文件缺失/不可读的条目计入
  M；选择范围内没有任何全文时导出一个空 zip（`0/0`），不是错误。

## 二、任务整包导出/导入（换机、交接、备份）

- **导出**：单个 zip，包含 task.json（已脱敏）、各筛选员的 `{slug}.db`、
  协作库、导入历史与全文 PDF（默认包含，可在对话框关闭）。
- **导入**：任意账号、任意部署上传该 zip → 预览源任务名/成员/体积/slug
  映射 → 确认后创建**新任务**；导入者成为新任务属主。不做自动合并，
  同名任务不会被覆盖；同一个包导入两次会得到两个独立任务。
- 单包上限 2GB；超限时界面会提示关闭「包含全文 PDF」后重试。
- 旧部署的成员授权不会随包迁移（避免旧用户 ID 在新部署误授权）；
  需要时请在新部署重新邀请成员。

## 三、数据安全声明

1. **规范命名只发生在导出副本上**。你任务里原始 PDF 的存储名、位置、
   `fulltexts` 登记表均不做任何原地重命名或改写——导出后再导入，文件会
   回到内部的单射安全命名存储，外部看到的只是归档副本的人话名。
2. 整包导出前会对 task.json 做脱敏：删除凭据/令牌/密码/环境路径等字段，
   并在 manifest 的 `redacted_fields` 里只记录**字段名**（不记录值）。
   包内不会包含账号凭据、JWT 或服务器环境信息。
3. 包内含全部研究数据（决策、全文、编码等），导出/导入端点仅任务属主
   （can_manage）可用；非参与者无法读取。
4. 导入是原子操作：校验失败（包损坏、成员校验和不符、文件缺失等）不会
   留下半成品任务目录，也不会改动既有任务。
5. 导出的 zip 内的 PDF 名字不包含服务器路径；内部 `fulltexts.path` 在导入
   时统一改写到新任务目录。

## 四、不做的事（明确边界）

- 不提供「原地重命名」或改写内部存储命名（会破坏防覆盖/防路径攻击的安全
  命名与幂等性）。
- 不做导入侧自动合并、不做跨任务全文库合并。
- 不做 PDF 内容抽取/重排版。
