# 木笔 ReviewFlow：导入文献使用引导

**适用版本：2.1.3 · 更新日期：2026年10月14日**

这份引导依据当前程序的实际行为编写。先按使用顺序解释怎么操作，再说明现有术语和容易混淆的地方，最后列出供你决定的改进问题。文中的改进建议尚未实施。

## 先读这一页：导入文献究竟要完成什么？

你要完成的是：**把检索文件中的文献加入当前任务，确认存疑的重复关系和书目信息，让可以使用的文献进入筛选。**

推荐顺序：

1. 确认当前任务，选择 RIS 或 Zotero CSV 文件。
2. 点击“解析文件并导入”，查看导入报告。
3. 在“导入核验”中处理重复候选。
4. 处理信息差异；无法判断的项目先留待稍后处理。
5. 在“待启用”中查看已具备条件的记录，点击“启用已核验记录”。
6. 进入标题与摘要筛选；需要时回到导入历史下载原文件、追溯来源。

**这里的“核验”是检查导入质量；“筛选”是判断文献是否符合你的研究纳入标准。** 确认两条记录重复，不等于把这篇文献判为研究中的“排除”。

首次导入可能自动让部分文献进入任务，不一定需要逐条核验、逐条启用。若任务已经保存过筛选、编码等研究记录，追加导入会采用更谨慎的暂存流程。具体区别见第4节。

## 1. 准备：先确认任务，再准备文件

### 1.1 谁可以导入？

当前流程由**任务所有者**导入文件、确认核验结果和启用文献。团队成员可按权限查看报告及历史；不能因为看到了页面，就认为拥有修改权限。

在开始前看清“当前任务”和“记录所属成员”，避免把检索结果导入另一个任务。

### 1.2 文件名就是来源名称

上传 `01-Wiley.ris` 后，产品中的导入来源名称就是 **01-Wiley.ris**，不会根据文件内部的数据库或出版社字段把它改成“Wiley”。

建议在上传前把文件名整理好：

| 文件 | 在产品中的来源名称 |
|---|---|
| `01-Wiley.ris` | 01-Wiley.ris |
| `02-Scopus.ris` | 02-Scopus.ris |
| `03-ERIC.csv` | 03-ERIC.csv |

同名文件会复用对应来源；不同文件名保留不同来源身份。同一篇文献可以同时来自多个文件，产品会保留这些来源关系。当前来源名称匹配会规范化大小写等差异，因此不要只靠大小写区分两次检索。

来源名称和来源类型是两件事。例如，“01-Wiley.ris”是名称，“数据库”是类型。需要生成 PRISMA 图时，来源类型可在首页的来源管理中确认；文件名本身不会自动保证来源类型正确。

### 1.3 支持什么文件？

本页面的文献导入支持 **RIS 和 Zotero CSV**。RIS 是书目记录文件，不是 PDF。文献导入与后续上传全文 PDF 是不同操作。

一次可以选择多个文件；当前上传接口接受 **1–20个文件**。任意自制 CSV 不一定符合 Zotero CSV 的字段结构。

## 2. “导入文献”页面的三个入口

| 页面选项 | 什么时候使用 | 主要作用 |
|---|---|---|
| 导入与报告 | 上传文件前后 | 选择文件、开始导入、查看本次结果及统计 |
| 导入核验 | 有需要确认的记录时 | 比较重复候选、确认书目信息差异、启用已解决记录 |
| 导入历史 | 需要追溯或继续旧批次时 | 查看历次上传、下载原文件、打开对应核验批次 |

**导入核验是导入文献页面的一个子功能。** 上传、解析、报告、原文件留存、来源追溯也属于完整的导入流程。

悬浮“导入待办”卡片只是导航提醒。点击标题可以收缩成胶囊；胶囊显示当前未完成事项。展开后可以跳转到相关操作。当前引导还包含“检查轨迹是否开启”，因此卡片没有隐藏，并不必然表示还有文献没有导入。

## 3. 选择文件并开始导入

1. 在“导入与报告”中点击上传区域，或把文件拖入上传区。
2. 检查文件列表。列表中的“移除”只移除尚未提交的选中文件，不会删除任务里已有文献。
3. 点击“解析文件并导入”。**仅选择文件还没有开始导入。**
4. 等待文件解析、匹配和保存。完成后查看报告；当前页面也可能自动切换到“导入核验”。

此时产品会读取文件中的题名、作者、年份、DOI等字段，并与任务已有文献及本次其他记录比较。可靠匹配可以由程序处理；存疑的题名相似、身份冲突和书目信息差异需要人工确认。

**“重复候选”表示可能重复，不表示已经判定重复。** 不能仅因为两个题名相似就一律确认重复。

## 4. 看报告：为什么有的文献能直接用，有的还要启用？

当前程序按任务是否已经产生研究工作来选择处理方式，而不只是按“是否第一次上传文件”判断。

| 任务状况 | 当前处理方式 | 你接下来做什么 |
|---|---|---|
| 尚未保存筛选、编码、全文批注等研究记录 | 采用初始导入流程，部分符合条件的记录直接进入文献库；题名等存疑候选仍需核验 | 查看报告和重复候选；有“待启用”记录时再启用 |
| 已保存过研究记录，包括团队成员的相关工作 | 新增来源记录先暂存，保留已有研究工作 | 核验存疑项目，再启用已解决的新增文献或来源关联 |

因此，第二次上传也可能仍采用初始流程；已经做过筛选的任务即使只上传一个文件，也可能采用追加暂存流程。页面中“初始导入／追加导入”的实际分界，与用户直觉中的“第一次／第二次上传”并不完全相同。

### 4.1 报告中的数字为什么不一样？

| 当前术语 | 用日常语言理解 | 不要误认为 |
|---|---|---|
| 总解析条数 | 这次文件被解析得到的书目记录条数 | 本次新增了这么多篇独立文献 |
| 来源记录 | 用于追溯导入出处的记录；同一篇文献可对应多条来源记录 | 去重后的独立文献篇数 |
| 已有匹配／来源关联 | 本批次来源记录已经关联到文献库中记录的数量；会随处理变化 | 全都是本次新增文献，或全都是待删除重复项 |
| 已启用新增文献 | 归属于本批次、已经加入文献库的新增独立文献 | 已经做出“纳入”筛选决定的文献 |
| 已激活来源记录 | 已完成启用的来源记录；既可能对应新文献，也可能只补充已有文献的出处 | 新增独立文献篇数 |
| 暂存待激活记录 | 尚未启用的来源记录，包括仍需核验或等待关联记录的项目 | 都已经核验好，马上可以启用 |
| 元数据待核验 | 仍未决定采用哪份书目信息的项目 | 需要判断研究纳入／排除的项目 |
| 待核验候选组 | 还没有解决的重复候选组 | 候选组内的记录条数 |
| 进入筛选（非重复总数） | 当前任务的可筛选文献总量；最终队列还受来源范围等设置影响 | 本次导入新增数量 |

这些指标统计的对象不同，有些相互重叠，**不要把所有数字相加当作文献总数**。

例如，同一篇文章同时出现在 `01-Wiley.ris` 和 `02-Scopus.ris` 中，可以有两条来源记录，但只对应一篇独立文献。若该文献原本已在任务中，补充来源后新增独立文献数量还可能是0。

## 5. 导入核验：按这个顺序处理

先在“批次”下拉框选中需要处理的上传批次。一次上传多个文件，也可以属于同一个批次。

### 5.1 五个分类分别是什么意思？

| 分类 | 你在这里看到什么 | 下一步 |
|---|---|---|
| 重复候选 | 尚未解决的可能重复记录组 | 比较后确认重复、不同文献，分别保留，或稍后处理 |
| 信息差异 | 已匹配到同一篇文献，但现有与导入书目信息不一致 | 保留现有信息，或采用导入信息 |
| 待启用 | 当前没有未解决核验问题、可进入启用流程的来源记录 | 启用已核验记录 |
| 已完成 | 当前已完成的来源记录，及部分已经作出结论的重复候选组 | 查看处理结果；这里并不是一个统一的“等待启用”队列 |
| 稍后处理 | 暂时无法判断的项目，或依赖其他批次／记录的项目 | 返回核验，必要时先处理关联批次 |

**“核验已完成”不等于“文献已启用”；“文献已启用”也不等于“筛选已纳入”。** 这是目前最需要区分的三件事。

当前界面会把部分任务级旧式重复核验组与所选批次的核验内容一起呈现，因此不要把每个分类数字都当作严格的“本批次文献篇数”。这也是后续需要统一的范围问题。

### 5.2 处理重复候选

逐项比较题名、作者、年份、期刊和DOI。需要时展开“查看原始来源记录”，检查实际导入内容。

| 操作 | 当前实际作用 |
|---|---|
| 保留此记录 | 选择确认重复时以哪条记录作为保留对象；只选单选框尚未提交 |
| 同一篇，保留所选 | 提交“同一篇文献”的结论，并建立重复记录与保留记录之间的关系 |
| 不同文献，分别保留 | 提交“不是同一篇文献”的结论，保留独立身份；新增暂存记录仍可能需要启用 |
| 稍后处理 | 保留未解决状态，不当作已经确认重复，也不当作不同文献，分别保留 |

如果候选包含已有研究工作的文献，当前流程要求保留已有有效文献，避免把其筛选和编码工作转移到新记录。若涉及多条已有有效文献，当前核验入口不会直接替你合并它们的研究工作。

提交成功后看见“已保存”，才表示这一项结论已经保存。选择保留记录和提交核验结论是两步。

### 5.3 处理信息差异

“元数据”就是**书目信息**，例如题名、作者、年份、期刊、DOI、摘要、记录类型和URL。它不是你的筛选决定，也不是编码值。

比较区默认只显示有变化的字段。需要查看完整对照时，取消“仅显示差异字段”。

| 操作 | 当前实际作用 |
|---|---|
| 保留现有信息 | 保存核验结论，继续使用文献库里的书目信息；不采用这次导入的差异信息 |
| 采用导入信息 | 用这份导入记录的书目信息更新现有文献，并保存核验结论 |
| 稍后处理 | 暂时不决定采用哪份信息，保留待核验状态 |

**“采用导入信息”会在确认时直接更新书目信息，不会等到点击“启用”才更新。** 当前操作采用的是整份相关书目字段，不是逐字段勾选，也不是只填补空白。导入字段为空时也应仔细比较。

如果现有书目信息已经被其他操作修改，这份旧差异建议可能无法直接采用。页面会限制采用旧建议，以免覆盖后来更新的信息。

有些地方仍使用“保留已有元数据”“接受导入元数据”等旧表述，它们与上述操作属于同一类书目信息核验，不是额外的新步骤。

### 5.4 什么时候可以批量处理？

| 批量操作 | 当前范围和条件 | 提交前看什么 |
|---|---|---|
| 批量确认重复 | 已加载、DOI一致、没有身份冲突且符合保留规则的候选；不包含仅凭题名相似的全部候选 | 弹窗中的候选清单和每组保留对象 |
| 批量保留已有信息 | 已加载且尚未决定的信息差异项目 | 确认清单中的项目都可以沿用现有书目信息 |

一次批量提交最多100项。**后台还有未加载记录时，批量操作只针对当前已加载且符合条件的项目，不代表整个批次都已处理。** 批量操作也不等于自动启用。

### 5.5 “稍后处理”不全是主动跳过

这个分类还可能包含等待关联记录的项目。例如，本批次文献与另一批次尚未启用的文献关联，需要先处理那个批次。出现“打开关联导入”时，先查看被依赖的批次。

不同项目的“稍后处理”目前实现不完全一致：重复候选的待定结论保存在服务器；信息差异的列表延期标记保存在当前浏览器，但未解决的信息差异本身仍在服务器保留。换浏览器时，不应把“稍后处理”列表视为跨设备一致的独立工作清单。

## 6. 启用：把已解决记录加入可用文献库或补充来源

核验后查看“待启用”，再点击“启用已核验记录”。确认弹窗会说明启用的作用及撤销限制。

当前按钮处理的是**所选批次中符合条件的记录**，不是只处理屏幕正在显示的这一条。它可能：

- 为任务加入新的独立文献；
- 把本次文件来源关联到已有文献；
- 跳过仍有重复疑问、未解决信息差异或关联依赖的记录。

不必等所有疑问都解决，才能启用已有的合格记录。2.1.3 根据服务器返回的可启用数量开放操作；其他记录仍在后台加载时也可启用。未解决的记录继续暂存。

启用过程中还可能发现关联记录的书目信息差异。若启用后仍有项目留在“信息差异”或“稍后处理”，继续核验剩余项目；不能简单把它理解为刚才的核验没有保存。

重复启用不会故意重复新增已经处理过的文献或来源关系。**不要把“已完成”再启用当作常规步骤**；先查看“待启用”数量和记录实际状态。

启用后进入标题与摘要筛选。若找不到某篇文献，再检查是否已启用、是否仍有候选或依赖问题，以及当前筛选来源范围是否包含它。

## 7. 撤销、追溯和离开页面

### 7.1 撤销上一步

“撤销上一步”用于撤销当前允许撤销的最近一次核验操作。批量核验作为一次操作，可在符合条件时整批撤销。

它不是删除整个导入批次，也不是随时回退所有历史。按钮是否可用取决于权限、后续操作及记录状态。**启用会结束相关导入核验的撤销窗口。** 因此，发现保留对象或信息选择错误，应在启用前及时撤销。

核验页面的撤销与筛选页面的撤销不是同一个操作：前者回退导入核验结论，后者回退筛选决定。

### 7.2 导入历史与原始记录

| 入口 | 用途 |
|---|---|
| 导入历史 → 下载原文件 | 下载当时实际上传的RIS／CSV，核对检索导出内容 |
| 导入历史 → 核验／继续 | 回到对应批次处理未完成项目 |
| 查看原始来源记录 | 查看某条导入记录的原始字段；当前为技术性内容，适合核对异常 |
| 导出来源追溯CSV | 导出当前选中批次的导入出处和处理关系，便于审计；不是筛选决策结果文件 |
| 轨迹 | 查看相关操作历史；导入核验历史与文献筛选决定需区分 |

原文件历史只覆盖已启用原文件留存功能后的上传；更早导入的文献不一定能在这里下载原文件。

### 7.3 离开页面前看什么？

确认刚才提交的核验操作显示“已保存”，并查看是否还有“待启用”项目。尚未解决的项目可以以后回来处理；任务中已有的有效文献仍可继续使用。

如果只是选了“保留此记录”，还没点击确认按钮，这个选择不等于已保存的核验结论。

## 8. 两个完整例子

### 例子A：新任务第一次导入两个数据库的检索结果

1. 上传 `01-Wiley.ris` 和 `02-Scopus.ris`，点击“解析文件并导入”。
2. 查看报告，区分文件记录条数与新增独立文献篇数。
3. 系统已直接处理部分可靠匹配；有题名相似候选时，逐组核验。
4. 两个记录确实是同一篇文献：选择保留对象，确认重复；只是题名相似但不是同一篇：不同文献，分别保留。
5. 查看“待启用”；若还有合格的暂存记录，启用后再开始筛选。若没有，不需要强行再启用“已完成”记录。

### 例子B：已经筛选过，再补充一份检索结果

1. 向原任务上传新的 `03-ERIC.ris`。产品识别到已有研究记录后，将新增来源记录暂存。
2. 核验重复候选，保护已有文献的筛选和编码工作。
3. 某篇已有文献的期刊或作者信息与导入文件不同：比较后保留现有信息，或明确采用导入信息。
4. 启用已解决的记录。已有文献可能只增加“03-ERIC.ris”这一来源关系；新文献才增加独立文献数量。
5. 继续筛选新增可用文献。仍未解决的项目以后再处理。

## 9. 当前已知困惑：不要把异常当作使用步骤

| 现象 | 目前可确认的情况 | 使用时如何判断 |
|---|---|---|
| 加载完成后又反复出现动画 | 2.1.3 同步读取版本并避免重叠刷新；真实导入变化仍会更新列表 | 不是要求重新核验，也不表示先前保存必然失败；不建议因此反复重新上传文件 |
| 已核验却不能启用 | “已完成”与“待启用”的范围不同；2.1.3 已取消等待整批加载的限制 | 看“待启用”与按钮状态；若确认存在尚未启用且已解决的记录却仍无法启用，应按状态异常处理 |
| 加载数量比文献篇数大 | 加载统计包含来源记录、候选组等不同对象 | 不能用加载数量作为去重后文献篇数 |
| 分类数字在加载时增加 | 当前分类计数根据已加载项目变化，未全部加载时可显示“≥” | 数字可能还不是最终值；不等于凭空新增文献 |
| 同一题名在不同地方出现 | 同一文献可能对应多个来源记录，也可能同时有重复和信息差异处理环节 | 先看是在显示出处、候选组还是独立文献；不能仅凭题名判断数据库重复新增 |

这些问题不能靠增加说明文字全部解决。它们涉及分类、计数、加载范围和操作边界，应在你审阅流程后针对性修改。

## 10. 供你审阅：哪些地方需要调整产品逻辑？

下列流程调整供后续讨论。2.1.3 已修复后台加载阻塞启用、刷新版本基线和异常保存提示；其余整体流程调整仍未实施。

| 问题 | 可讨论的调整方向 |
|---|---|
| “已完成”同时混合处理结论和启用状态 | 明确区分“核验通过待加入”与“已加入任务”；已经存在的文献也给出清楚状态 |
| “待启用”被理解为还要人工核验 | 将动作表述为“加入任务／补充来源”，明确它不会自动作出研究纳入决定 |
| “初始／追加”的判断与上传次数不一致 | 让用户理解依据是是否已有研究工作；是否统一成一种导入流程，由你决定 |
| 信息差异确认与启用的生效时点不同 | 是否把书目信息更新也延后到最后统一确认，或保留立即更新但明确提示 |
| “保留记录”与“保留信息”相似，但作用不同 | 前者明确是在确认同一篇文献，后者明确是在选择书目信息版本 |
| 批次核验混有任务级旧式重复候选 | 是否统一到清晰的批次范围，并单独呈现任务范围的遗留核验 |
| 计数混合来源记录、候选组和独立文献 | 各处注明单位，主要进度只围绕用户要处理的事项呈现 |
| 启用按钮必须等历史记录加载完 | 根据服务器确认的可处理记录开放操作；历史记录不应阻塞当前工作 |
| 加载完成后又反复出现动画 | 优先保留已加载缓存，仅在相关数据变化时更新必要部分 |
| “稍后处理”既表示暂缓判断，又表示关联阻塞 | 明确区分用户主动暂缓和需要先处理关联记录，并考虑跨设备一致性 |
| 用户觉得多数重复候选都可以直接确认 | 在保持可靠身份判断的前提下，优化自动处理范围和可审阅的批量确认；不把题名相似直接当作确定重复 |
| 撤销边界不直观 | 提交与启用前明确哪些操作可撤销、什么时候窗口结束 |

你可以按本表逐项批注，或直接指出“第几步应该怎么做”。下一轮修改应以你确认的流程为准。
