## 1. 适用范围和既有功能

- 目标是已确认的团队逐条终局工作流：同条目本轮全部应筛参与者完成，统一纳入自动推进，统一排除停止，分歧等待授权仲裁最终纳入。
- 保留同一阶段内的独立、并行、双盲提交；改变的是提前进入后续阶段的资格，不回写个人意见来伪造一致。
- 不以 server/desktop 或 AUTH_ENABLED 一个开关决定适用范围。既有 `task_kind` / `team_latched` 是取证线索，须证明它们怎样区分共享团队、独立本地协作、独立筛选后合并、solo 及手工分析。
- 不把“曾共享过”当作任意旧身份都是当前必需参与者，也不自动豁免所有 desktop 团队或所有单人历史。先给出具体模式真值表；无法区分的存量情形必须暴露，不能静默猜测。
- 无账号/无 grant 的合法本地、legacy、导入作者等身份按其既有工作流和明确来源识别；不能仅凭成员表/账号开关排除。

## 3. 逐条资格层

### 初筛 → 复筛

- 必需参与者或必要业务角色未配置：等待配置，空集合不得自动满足；一名明确应筛成员的集合合法，旧 CSV 合并工具的 2–9 包限制不借入新资格层。
- 任一必需成员本轮未完成该条目：等待成员。
- 全员纳入：终局纳入；全员排除：终局排除。
- 有纳/排分歧：等待该条目的有效授权仲裁；最终纳入才可复筛，最终排除停止。

### 复筛 → 编码 / 评价

- 同样按当前复筛全员意见及有效复筛仲裁决定；不得回退“本人初筛纳入”放行编码。
- 还须满足当前上游初筛终局纳入，不能用旧复筛记录绕过已变化的上游状态。
- 仲裁纳入后，包括曾个人排除的应筛成员也能进入下一轮，不改其原始个人意见。
- 单条已合格不因另一文献未完成而被整批锁住。

### 接口一致性

- 队列、计数、详情/当前工作入口、直接和批量保存使用同一资格服务，不以个人完成比例或页面导航代替服务端门。
- 编码/评价的当前处理资格与历史查看分开；保留已有权限，历史不因上游变化被删除或失去审计入口。
- 只阻挡相关团队工作流，独立/solo/未关联筛选条目的合法手工分析路径不得被误锁。
- 正式纳入/排除二选一保持，待成员/待仲裁等是流程状态，不是新的投票选项。

## 4. 仲裁可用性、双盲和绑定

- 必须解决现有“全阶段 paused 后才可合并/仲裁”与逐条推进的冲突：对本条已全员完成的冲突可进入合法仲裁，同时不透露其他未完成条目的个人意见。desktop team 也必须具有该合法解决路径，不能只加 gate 却让冲突无解；批量 server 链和独立 CSV 工具保持原能力边界。
- 保留旧的批量暂停/离线合并用途；提出最小的新逐条会话/来源扩展，不全局移除双盲保护。
- **不改变通用 CSV/离线历史和 generic latest 的既有语义。** 上传包本身有合法用途，不能仅因它覆盖 generic latest 就当作越权。
- 新终局消费者只采纳经验证的 task、item、stage、本轮/版本、必需参与者及当前判断输入绑定的授权结论。未经绑定的 CSV 不能成为当前团队真相；点击“确认覆盖”不能替代绑定验证。
- 可新增专用适用结论查询，保留通用 latest/history；合法离线结果如何参与其原工作流按源码证明，不一刀切禁止 CSV。
- 绑定要**逐条**：A 的成员判断变化使 A 的旧结论失效；B 的无关判断变化不应仅因整批 merge SHA 变化而废弃 A 的有效结论。现有 `merge_sha256` 能否支持此语义必须核实。
- 仲裁员在作出结论时的授权与其后角色变化分开；不能随意抹掉当时合法的历史结论。成员集合/轮次变化的适用性规则需明确。

## 5. 后端改动清单（准备阶段须落到真实文件/符号）

5. 撤销后的活动显示与现行输入收敛；不新增未经身份/路径证明的物理清理。

## 7. 存量与验收

- 不删除个人判断、已编码/评价记录或历史仲裁；不重算旧研究结果，不自动改个人意见。新的资格读取时派生；不合格的存量后续记录保留为历史并明确当前资格。
- 补齐 actor 模式、owner 管理-only、纯仲裁员、已移除、缺席、身份别名、当前轮次、零参与者、独立/solo/本地协作/离线导入回归。
- 两阶段全员纳/排、未完成、待仲裁、有效/过期仲裁、跨阶段不混用、直接/批量提交不可绕过均须真实隔离 API 验证。
- 必测：同条 A 全员完成且另一条 B 未完成时 A 可合法仲裁/推进；B 后续变更不误废 A，A 自身变更应使旧结论过期。
- 历史 κ/导出/离线合并不被现行输入过滤静默改义，名单显示残留与撤权 403 分开回归。
- `import_sources raw_json='null'` 可达性未证，作为独立候选记录，不夹带一行式迁移修复。

## 8. 裁决后轨迹、历史只读（2026-11-15 用户新增裁定）

用户原话：“一旦裁决后就不允许在轨迹、历史里面更改”。本节覆盖此前允许通过历史回溯修改已裁决结果的解释。

- 裁决生效后，对应条目、对应阶段的研究轨迹和历史记录只供查看；禁止从这些入口编辑、删除、撤销、恢复旧记录或覆盖写回。属主、管理员和仲裁员均无旁路。
- 后端根据实际任务、条目、阶段及已生效裁决判定，在受保护的保存窗口内检查，再调用真实 writer；直接 API、批量及回放请求须执行相同规则，不能信任客户端只读标记。批量操作触及受保护内容时整次拒绝，零业务写入。
- 不能只靠“当前证明是否仍适用”决定能否从历史改写已经裁决的内容；证明过期本身不构成历史编辑解锁许可。
- 此限制按条目和阶段实施；未裁决内容的合法撤销、其他条目的合法操作及后续阶段的正常工作继续按既有资格规则处理。不增加重开或强制解锁功能。

后端改动清单：将规则接入有任务上下文的 history/trace restore/undo 服务和路由，并与裁决提交共用相应保护窗口，覆盖“页面打开后裁决才生效”的竞争；拒绝后不得改动业务、journal、trace 或请求摘要。A1 通用借用连接原语不自行打开 collaboration.db 查询业务状态。保留历史读取、导出和现有访问权限，不全局改 generic latest/CSV/CLI 的历史用途。

前端改动清单（仅规格，custom_frontend 仍只读）：研究轨迹详情及历史列表/详情中，涉及已裁决条目和阶段的编辑、删除、撤销、恢复操作统一禁用，显示“已裁决，历史记录仅供查看”；词典键定为 `team.history.read_only_after_arbitration`，英文为“Adjudicated. History is read-only.”，后续交接提供十语言映射。服务端冲突返回后刷新对应只读状态，并使用同一提示；保持查看和既有导出入口，不按整任务粗暴禁用其他条目。

必要验收：已裁决 include/exclude 两类均拒绝历史改写；属主和普通成员均不可绕过；直接请求和裁决并发均零业务写；同条目不同阶段、不同条目和未裁决撤销的合法正控保留；原历史内容仍可按权限查看。实施与真实验证尚待 S2 后续路由接线，写入合同不代表代码已完成。

## 9. 已完成阶段保留结论，成员变动只影响未完成阶段（2026-11-15 用户确认）

用户对“已经完成的条目，保留完成时的结论；新成员参与尚未完成的阶段”明确回复“同意”。本节是人类新增裁定，覆盖§2、§3、§4、§7中可能将已完成阶段随当前名单或判断变化重新计算、作废的旧解释。主控先前自行设计的“已裁决条目允许无旧痕迹的新成员补交首票”不采用，不作为实现或验收依据。

- 完成按“文献 × 阶段”记录，包括全体应筛成员一致形成的终局纳入/排除，以及当时合法授权的仲裁形成的终局纳入/排除；部分成员完成、分歧尚未裁决均未完成。
- 未完成阶段仍按当前明确应筛名单及必要角色判断。成员新增、移除或筛选职责变化后重新检查尚未完成阶段；旧名单下准备中的仲裁不能直接提交。
- 已完成阶段保留完成时的名单、意见依据、结果和完成来源。正常人员变化本身不使其失效、不补历史意见、不重新变成待办；不通过修改旧个人意见来适配新名单。
- 初筛终局纳入、复筛未完成：新成员按其当前角色参与复筛，不补初筛；初筛终局排除：仍停止；两阶段均终局纳入：按当前角色及后续流程参与编码或协调。
- 已完成阶段维持完成及只读状态，不增加重开、补票或强制解锁功能。§8的已裁决历史保护继续生效；未完成阶段的合法撤销、其他条目、后续阶段和历史读取/导出保留。
- 完成依据必须可验证、持久保存，并与最后一票或仲裁的实际提交以及成员变动有明确先后关系；不能仅凭页面曾显示完成、旧缓存或当前没有某条票来推断历史完成。
- 存储损坏、任务/库身份不一致、来源无法验证不当作正常人员变化，也不能借本节接受任意旧 CSV/generic latest。存量只确认能证明的事实，不编造已经丢失的完成时名单或前史。

后端清单：持久化逐条逐阶段完成事实及其输入快照；在队列、详情、计数、保存门、当前结果和 PRISMA 中统一消费；未完成部分继续当前名单服务；名册/职责变更与最后一票、仲裁提交串行并保留单库提交边界；历史写保护消费对应完成状态。generic CSV/latest/CLI、独立/solo/合法本地用途不全局改义。具体存储和事务接缝先做实际影响分析及独立设计复核，禁止将跨库顺序提交称作全成全败。

前端清单（仅规格，custom_frontend仍只读）：已完成阶段继续显示完成和只读状态，并可查看完成时参与名单、意见及结果来源；新成员待办从其有权参与且尚未完成的阶段开始；未完成阶段名单变化时刷新待成员/待配置/待仲裁状态。区分“全员一致完成”和“仲裁完成”，不把二者混写成已裁决；精确接口字段、错误码与十语言键随接线交接。
