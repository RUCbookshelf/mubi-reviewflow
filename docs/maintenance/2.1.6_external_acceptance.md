## 3. Jev 测试钥匙轮换（账号侧，用户操作）

仓库侧无任何钥匙值，本单亦不收集、不存储、不展示新旧钥匙值。操作全部在 CommandCode 后台（用户账号），代理不可代做。

步骤：
1. 登录 CommandCode 后台，进入测试钥匙管理页。
2. 新建一枚新测试钥匙（仅自用；不写入任何文档、聊天、截图）。
3. 在应用「决策模型」设置中把 API Key 更新为新钥匙（厂商选 TypeSafe 官方端点，即 Jev 官方 API）。
4. 功能验证：用决策模型的真实去重功能跑一次（导入一批含重复的题录并执行复核），确认调用成功。
5. 在后台撤销/删除旧测试钥匙。
6. 复验：再跑一次决策模型功能，确认新钥匙正常；若仍有旧钥匙引用会在此暴露。

**完成标准（两条同时满足）**：
- 旧钥匙已失效（后台显示已撤销，或旧钥匙调用被拒绝）；
- 新钥匙功能验证通过（第 4/6 步成功）。

**记录方式**：仅在 BACKLOG 2.1.6 第 5 条（EXT-02 Jev 钥匙轮换）销项时写「已轮换 + 日期 + 结果」一句话；不写钥匙值。若暂不做，保留待验状态——本单交付不构成核销。（更正：初稿误写「第 9 条」——第 9 条实为 OPS-01 发布前核对，与本销项无关。）
