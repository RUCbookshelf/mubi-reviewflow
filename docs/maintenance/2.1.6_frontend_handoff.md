## 1. 后端现在返回什么（8 个保存失败分支）

失败时仍是 **HTTP 400**，但 `detail` 从「裸英文字符串」升级为五键对象：

```json
{
  "error_code": "invalid_judgement",
  "message_key": "analysis.rob.legacy_save.invalid_judgement",
  "params": {"domain": "missing outcome data"},
  "details": "invalid domain judgement: missing outcome data",
  "message": "invalid domain judgement: missing outcome data"
}
```

- **`message` 与 `details` 逐字节等于改造前的原文**（含 `": {域名}"` 后缀）——
  后端测试用字面量钉住，任何人改 `save_rob` 文案该测试即红。
- `message_key` 使用**独立命名空间** `analysis.rob.legacy_save.<error_code>`，
  **不是** v2 的 `analysis.rob.<error_code>`。原因见 §3，务必不要混用。

### 1.1 逐键对照（8 条）

### 1.2 域名的两个坑（前端把 `params.domain` 直接插值即可，不要自己解析文本）

- `params.domain` **已是完整域名字符串**，原样用于 `{0}` 插值。
- QUADAS-2 的 applicability 域名**本身含 `": "`**：
  `"applicability: patient selection"`、`"applicability: index test"`、
  `"applicability: reference standard"`。后端按**首个** `": "` 切分，故
  `params.domain` 不会被截断；前端**不要**对 `message` 再跑 `split(': ')` 取域名。
- 未知域名（不属于该框架）也走 `invalid_judgement`，`params.domain` 即用户填的原名。

## 2. 前端待实施清单（逐项，含验收断言）

### 2.1 `analysis_rob_editor.js::serverError()` 改为先按机器码

**现状**（:108-117）：对 `error.message` 做英文文本匹配——2 条正则
（`/^domain rationale is required: (.+)$/`、`/^invalid domain judgement: (.+)$/`）
+ 5 条 `known` 精确表，命中后 `T('robEditor.xxx')`；未命中走
`WorkflowControls.errorText(error)` 兜底。

**要求**：在函数**最前面**插入**按 `error.errorCode` 查明示映射**的机器码优先分支：
先查下方八码映射表选规范键 `analysis.rob.legacy_save.<code>` 并传 `error.params`——
**不得以对象自带的 `messageKey` 作为首选查找键**（已知码的映射不因载荷缺键/错键而丢失）。
规范键渲染未命中（词典未登记/译文未命中）时**不得落回读取 `error.message` 的原有回退**——
错键载荷下 `error.message` 已被 `errOf` 用错键译文覆盖（见下方要点），必须改按
`errorCode`+`params` 直取既有旧文案（② `legacySaveFallback`）。
**原正则/known 表全部保留在后面**（旧服务器 / 旧缓存前端仍只有裸字符串，删掉即破兼容）；
但**只有未知码/无码错误**才允许到达该回退与 `errorText`。

```js
/* 八个已知机器码 → legacy_save 规范键的明示映射（顺序 = 后端 save_rob 分支序）。
   规范键是 errorCode 的纯函数：已知码的文案选择不读对象自带的 messageKey，
   也不读 error.message——errOf（index.html:5506）在构造 ApiError 时会先用
   messageKey 命中词典的译文覆盖 error.message，载荷错键会把原文污染成错文案。
   映射表必须用 null 原型：未知码查表不得误命中 Object.prototype 的
   constructor/toString 等继承属性（普通对象字面量会命中且为真值）。 */
const LEGACY_SAVE_KEYS = Object.assign(Object.create(null), {
  unsupported_framework: 'analysis.rob.legacy_save.unsupported_framework',
  fields_required: 'analysis.rob.legacy_save.fields_required',
  invalid_overall: 'analysis.rob.legacy_save.invalid_overall',
  overall_rationale_required: 'analysis.rob.legacy_save.overall_rationale_required',
  invalid_judgement: 'analysis.rob.legacy_save.invalid_judgement',
  domain_rationale_required: 'analysis.rob.legacy_save.domain_rationale_required',
  domains_incomplete: 'analysis.rob.legacy_save.domains_incomplete',
  source_unlinked: 'analysis.rob.legacy_save.source_unlinked'
});

/* 规范键未注册时的可信旧文案回退：按 errorCode+params 直接调用既有旧 formatter
   （§1.1 文案源），不读可能已被错键译文覆盖的 error.message，也不转交会再次
   消费错键 messageKey 的 WorkflowControls.errorText。域参数按旧 formatter 原用法
   传入：先 T() 本地化域名再位置插值 {0}（§1.2 完整域名，不输出 [object Object]）。 */
function legacySaveFallback(error) {
  const domain = (typeof error?.params?.domain === 'string' && error.params.domain) ? error.params.domain : null;
  switch (error?.errorCode) {
    case 'unsupported_framework': return T('robEditor.framework_required');
    case 'fields_required': return T('robEditor.fields_required');
    case 'invalid_overall': return T('robEditor.overall_invalid');
    case 'overall_rationale_required': return T('robEditor.overall_required');
    case 'invalid_judgement': return domain ? T('robEditor.domain_judgment', T(domain)) : null;
    case 'domain_rationale_required': return domain ? T('robEditor.domain_reason', T(domain)) : null;
    case 'domains_incomplete': return T('robEditor.domains_required');
    case 'source_unlinked': return window.RFServerMessage?.('analysis.rob.source_unlinked') || null;
    default: return null; /* 未知码/无码不在此回退，走原有通用路径 */
  }
}
function serverError(error) {
  /* 新增第一分支：机器码优先。已知码的文案选择只由 errorCode+params 决定：
     ① 规范键已注册 → RFServerMessage(规范键, params)（具名 {domain}，见 §2.2.1）；
     ② 规范键未注册 → legacySaveFallback 按 code+params 直取既有旧文案；
     ③ 仅当 ①② 均未产出文案时的最后手段：原样透传 message 兜底——已知码绝不
        转交 errorText（其会再次消费可能错键的 messageKey）。注意：规范键已注册
        但 params.domain 违反 §1.2 契约缺失时（后端测试钉住，按契约不可达），
        ① 会返回含字面 {domain} 的译文（interpolate 对缺失具名 token 原样保留）
        而到不了 ③；③ 不承诺对不可达载荷原样透传。messageKey 缺失或错键都不得
        使已知码失去映射。 */
  if (error && Object.hasOwn(LEGACY_SAVE_KEYS, error.errorCode)) {
    const keyed = window.RFServerMessage?.(LEGACY_SAVE_KEYS[error.errorCode], error.params);
    if (keyed) return keyed;
    const fallback = legacySaveFallback(error);
    if (fallback) return fallback;
    return error?.message || '';
  }
  const text = error?.message || '';
  /* ↓↓↓ 以下为原有英文匹配回退，仅未知/无码错误到达此处，保持不变 ↓↓↓ */
  for (const [pattern, key] of [[/^domain rationale is required: (.+)$/, 'robEditor.domain_reason'],
                                [/^invalid domain judgement: (.+)$/, 'robEditor.domain_judgment']]) {
    const match = text.match(pattern); if (match) return T(key, T(match[1]));
  }
  const known = {'overall rationale is required':'robEditor.overall_required','all framework domains are required for a completed assessment':'robEditor.domains_required',
    'all result, reviewer, judgement and source fields are required':'robEditor.fields_required','unsupported risk-of-bias framework':'robEditor.framework_required',
    'invalid overall judgement':'robEditor.overall_invalid'};
  return known[text] ? T(known[text]) : (window.WorkflowControls?.errorText?.(error) || text);
}
```

要点：

- `ApiError` **已**携带 `error.errorCode` / `error.messageKey` / `error.params` /
  `error.code`（`index.html:5524-5526`，对象载荷无条件提取）——**无需改传输层、
  无需重做 ApiError**。
- 为什么首选 `errorCode` 而非 `messageKey`：`messageKey` 由载荷给出，可能**缺失**
  或指向**别的键**（不匹配）；八个已知码的语义由 `error_code` 决定，规范键是
  `errorCode` 的纯函数，映射因此不依赖载荷自报的键。**且 `error.message` 本身
  可能已被污染**：`errOf`（`index.html:5506`）构造 `ApiError` 时执行
  `keyed || (source && T(source))`，只要 `messageKey` 命中任何已注册键（例如
  误指 v2 的 `analysis.rob.invalid_overall`），`error.message` 就被替换成那个
  键的译文——错键场景下原英文匹配正则必然失配。因此已知码的回退（②）按
  `errorCode`+`params` 直取旧文案，**不读 `error.message`，也不落
  `WorkflowControls.errorText`**（其首选分支 `workflow_controls.js:142` 会再次
  消费同一个错键）。`messageKey` 的键化渲染继续由既有 `WorkflowControls.errorText`
  负责（未知码/无码错误若带已登记 messageKey，仍经 errorText 出文案）。注意：409
  `analysis.rob_ambiguous_scope` 旧键**当前前端未注册**（词典无该注册点），其
  `messageKey` 键化渲染不命中，仍走 errorText 通用路径——本地化基句 + `message`
  原文；补登该键属**另行前端本地化待办**，不在本单八码范围内，后端 409 键与八码
  规格均不变——两条路径职责不变。
- 兼容双保险：新键**尚未注册**时已知码由 ② 给出既有旧文案（§1.1 文案源，当前
  界面语言的现成译文），词典登记前后已知码输出稳定——不再依赖「正则/known 表
  照常命中原英文」的旧假设（该假设在错键污染场景不成立，见上条）。未知码/无码
  错误仍走原英文匹配 + errorText 原路径，行为与今天一致。

#### ⚠️ 2.2.1 占位符必须是**具名** `{domain}`，不能沿用 `robEditor.*` 的 `{0}`

这是实测坑（用真实 `index.html` 的 `interpolate`/`T`/`RFServerMessage` 跑过）：

```text
RFServerMessage('analysis.rob.legacy_save.invalid_judgement', {domain:'applicability: patient selection'})
  源串 '请选择「{0}」的判定。'      -> "请选择「[object Object]」的判定。"   ← 坏
  源串 '请选择「{domain}」的判定。' -> "请选择「applicability: patient selection」的判定。"  ← 对
```

原因：`RFServerMessage(key, params)` 把 **params 对象整个**作为 `T()` 的第一个位置参数
（`T(source, params)`）；`interpolate` 对 `{0}` 取 `args[0]`，得到的就是那个对象本身，
于是 `String(obj)` = `[object Object]`；而 `{domain}` 走具名分支
（`Object.hasOwn(params,'domain')`）取值正确（数组值会以 `, ` 连接）。

因此第 5、6 条**不要**直接复用 `robEditor.domain_judgment` / `robEditor.domain_reason`
的 `{0}` 源串，两个可行做法（推荐前者）：

1. **推荐**：为这两个 legacy 键**新写具名源串**（十语言），例如
   `'请选择「{domain}」的判定。'` / `'请填写「{domain}」的判断依据。'`，
   外语槽可逐字沿用原译文但把 `{0}` 改成 `{domain}`。
2. 或在 `serverError()` 里对这两码特判，绕开 `RFServerMessage`：
   `return T('robEditor.domain_judgment', error.params?.domain)`（位置式 `{0}` 可正常工作，
   已实测）。但这会在两处维护文案映射，不如做法 1 干净。

其余 6 条无参数（`params: {}`），不涉及占位符。

- **不要**把这 8 个键塞进 `analysis_rob_locale.js` 现有的 `analysis.rob.<code>` 表：
  该文件用 `Object.entries(rows)` 批量注册为 `'analysis.rob.' + code`，
  且 `build/tests/analysis_rob_locale.test.cjs` 有硬断言「注册的 key 集合必须
  **恰好等于** 55 个 v2 code」——混入即红。建议**新增独立 locale 片段**
  （如 `analysis_rob_legacy_locale.js`）并在 `index.html` 加 `<script>`。
- 词典资产令牌：`index.html:10296-10298` 现有
  `analysis_rob_locale.js?v=20261112-r67`、`analysis_rob_editor_locale.js?v=20261112-ui-polish`、
  `analysis_rob_editor.js?v=20261112-ui-polish`。改动其中任一文件**必须 bump `?v=`
  令牌**（仓内 MM5-01 会逮工作树变更），新增文件也需带令牌。

> （probe 标记文案「总体判定格式无效。」）当成该码的文案显示。

## 3. 为什么是独立命名空间（务必不要改成 v2 的键）

v2 的 `analysis.rob.<code>` **已注册十语言**（`analysis_rob_locale.js`，55 条）。
若旧保存路径复用该键，`errOf` 的 `keyed` 会立刻命中，把 `payload.message`
**替换成 v2 的中文/当前语言文案**；而 `analysis_rob_editor.js::serverError()` 今天
靠**英文原文匹配**（5 个 known 键 + 2 条正则）——一旦 `error.message` 变成译文，
这些匹配当场失效，旧客户端行为被改变。

用 `analysis.rob.legacy_save.<code>`：今天词典里不存在 → `RFServerMessage` 返回 `null`
→ `errOf` 回退 `payload.message` 原文 → **旧客户端逐字不变**。前端注册新键后才切换。
这也是为什么后端测试能同时保证「新结构可机读」与「旧文案逐字节不变」。
（同一 `error_code` 值复用 v2 词表只影响**统计口径**，不影响文案查找路径。）
