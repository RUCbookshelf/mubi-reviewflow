# AI 抽取建议（BYOK）使用说明与治理边界

- 适用版本：2.1.4 起。功能**默认关闭**；不开启、不配置钥匙时，本功能对界面与既有流程零影响。
- 本文是产品的正式披露文档：治理原则、数据流、钥匙存放、失效场景与边界。

## 1. 治理原则（P1–P10）

| # | 原则 | 实现位置 |
|---|---|---|
| P1 | 人是唯一责任主体：AI 只建议，采纳逐条人工确认，建议永不自动落库为编码事实 | 建议卡逐条 采纳/编辑后采纳/忽略；采纳只把值填入表单控件，保存仍走既有编码保存链路 |
| P2 | 默认关闭 | 任务 AI 设置总开关，默认 off |
| P3 | BYOK 钥匙自持 | 个人钥匙仅本人可写/删；界面只回掩码（仅尾 4 位） |
| P4 | 无溯源不展示 | 每条建议必须带原文引文；**服务端核验引文出现在全文或摘要中**（完整逐字命中且引文 ≥8 字符=完全核验"引文核验"；短于 8 字符的命中引文与超 80 字引文按可核验前缀放行的一样，在建议卡标注"部分核验"）；**核验只证明引文逐字存在于原文，不核验、也不代表建议值正确**；核验不过或无引文的建议在服务端丢弃，不进入界面 |
| P5 | 逐条确认 | 不提供批量一键采纳 |
| P6 | AI 身份留痕 | 建议与决策均记录 provider/模型/提示词版本/时间；研究轨迹记录 `ai_suggestion_generated` / `ai_suggestion_decided` |
| P7 | 可复现可报告 | 一键生成中文/英文 Methods 段落（含所用模型清单、字段范围、统计、密钥模式） |
| P8 | 审计导出 | 逐条决策可导出 CSV/JSON（含建议值、最终值、引文、页码、时间）；导出不依赖任务开关，有记录即可导出 |
| P9 | 字段分级 | 首期仅开放 7 个研究特征类字段白名单（发表年份、资助来源、样本量、研究设计等）；结局与偏倚风险等高影响字段不开放 |
| P10 | 先验证后放量 | 设置页展示本人使用统计，并提示先在 20–50 篇人工编码样本上核对建议质量再扩大使用 |

## 2. 数据流（一次建议请求经过什么）

1. 用户在编码页点「AI 建议」（或开启自动触发后进入文献自动获取一次）。
2. 服务器组装提示词：字段定义 + 文献题录 + 摘要 + 全文 PDF 文本（按页，超长时先裁全文页、题录与摘要永不裁掉；截断量随警告展示）。
3. 请求经服务器发往**用户配置的 OpenAI 兼容端点**（云端或本地 `http://127.0.0.1:11434/v1` 等）；`Authorization` 头携带钥匙；**不跟随 3xx 重定向**（防止钥匙被转发到未配置的主机）；响应读取上限 2 MiB。
4. 服务端解析模型 JSON：无引文的建议丢弃；**引文在全文/摘要中定位不到的建议丢弃**；短于 8 字符的命中引文与超 80 字引文（按可核验前缀放行）均标注"部分核验"；页码以服务端定位结果为准（命中正文给页码可跳转；仅命中摘要的建议标注为摘要来源，无页码、不提供跳页）。
5. 建议存入个人库（状态 pending），轨迹记录生成事件（不含钥匙与请求载荷）。
6. 用户逐条决定：采纳（填入映射的编码维度控件或复制）/ 编辑后采纳 / 忽略；决定与最终值入库并记轨迹。

## 3. 钥匙存放与可见性

- 位置：数据目录下 `.ai_keys/personal_{用户ID}.json`（个人）与 `.ai_keys/shared_{任务ID}.json`（任务共享，仅负责人可配置）。**不在任务目录内，不进入任何任务导出包/备份包**（有回归测试锁死）。
- **明文落盘，一期不做加密**：文件内容为 JSON 明文，文件权限 0600/目录 0700 为"尽力而为"（Windows 下系统级隔离不保证）。真正的防线是：界面永不回显明文（只显示尾 4 位掩码）、不存在读取他人钥匙的任何功能、钥匙不进日志/轨迹/错误消息/导出包。
- 桌面版：数据目录即本机。服务器版：数据目录在服务器上——个人钥匙由服务器进程代为保管与使用，**服务器管理员（有文件系统访问权的人）可见**；如不可接受，请使用自己的本地模型端点或不在服务器模式存放钥匙。
- 共享钥匙模式：负责人配置一次，成员进入任务即可用（无需各自填钥匙）；成员只能看到"任务已启用 AI（服务商名）"，看不到钥匙本身；请求以任务名义经服务器发出。
- 环境变量 `REVIEWFLOW_AI_KEY`（管理员模式）：存在时视为全局个人钥匙，不可从界面删除。

## 4. 出站与内网披露（服务器模式必读）

- 所有 AI 请求**由服务器发起**。服务器模式下，任何被邀请的成员都可以配置自己的 `base_url` 并触发请求，因此**成员可让服务器访问公网 http(s) 地址并据响应差异（状态码/连接成败，不含响应体内容）做有限探测**。请仅在成员半可信的团队中启用；面向不受信成员的部署应改用管理员统一配置（环境变量）或网络层限制。
- 缓解措施（已内置，**属尽力缓解而非安全边界**）：禁止重定向；响应体 2 MiB 上限；**provider 非 2xx 响应只回状态码与固定文案、响应体内容不回显**（可据以探测的只剩状态码/连接成败差异，不含响应体内容）；base_url 含控制字符在保存前即被拒（422）；**内网地址阻断**——链路本地（169.254.0.0/16、fe80::/10）、IPv6 唯一本地（fc00::/7）、常见云元数据地址、RFC1918 私网段（10/8、172.16/12、192.168/16）与 CGNAT 段（100.64.0.0/10）在保存与出站两处均拒（含 IPv6 映射、十进制 IPv4、尾点等字面变体）；**域名形式做一次 DNS 解析复核**，解析到上述地址段即拒（解析失败不拦，按出站网络错误降级）；**回环地址按运行模式分流**——桌面模式保留（本地模型（如 Ollama）是一期卖点），服务器模式一律拦截；同一时刻出站调用并发上限 8，超限返回 503（ai_provider_busy）。

## 5. 成本提示

BYOK 模式下 token 费用由你的钥匙账户承担。每次生成会展示本次用量（usage）；全文越长消耗越多（超长全文会截断，见 §2）。建议先用少量文献试算费用，再批量使用。

## 6. 失效场景（如实披露）

- **扫描版/图片型 PDF**：抽不出文本层，建议质量差或无建议（无全文时退回摘要；摘要也无则提示无法生成）。
- **数据只在表格/图形中**：模型可能读不到或读错，核验引文可能因此丢弃建议——这是保守行为，不是缺陷。
- **模型幻觉引文**：服务端引文核验会丢弃定位不到原文的建议；你能看到的每条建议的引文都经过核验（"引文核验"角标=≥8 字符引文逐字存在；"部分核验"角标=引文过短或仅前缀逐字存在，尾段未逐字核验，采纳前请自行对照）。核验只针对引文本身，不证明建议值正确。
- **升级前创建的旧任务（无负责人）**：无法启用 AI；当前版本**没有自助认领入口**，界面会如实说明并建议在桌面版重建任务协作或联系服务器管理员。
- **建议≠事实**：所有建议仅作参考，采纳前请对照引文核验原文；模型输出未经独立验证。

## 7. 已知边界（一期）

- 字段映射（建议字段→编码维度）保存在配置者本机浏览器 localStorage，仅对配置者生效；其他成员的"采纳"走复制粘贴。
- Methods 报告与审计统计按成员本人维度；团队汇总需各成员分别导出。
- 删除任务时共享钥匙文件不会自动清理（位于数据目录而非任务目录）；如需彻底撤销，请先在任务设置中删除共享钥匙再删除任务。
