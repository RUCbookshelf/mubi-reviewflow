# 2.1.5 外部 AI HTTPS 兼容补丁 / External AI HTTPS hotfix

[中文](#中文) · [English](#english)

## 中文

### 修复什么

本补丁适用于 **ReviewFlow 2.1.5 源码部署**，修复在 Python 3.12 等新版运行环境下，测试 API Key 或请求 AI 建议时显示“服务暂时无法完成请求，请稍后重试”的一类错误。

原因是共享 HTTPS 连接器读取了新版 Python 已移除的属性，请求在到达 AI 平台前就发生异常。补丁保留旧版 Python 的参数语义，并兼容新版接口；证书校验、目标地址防护和重定向规则保持原样。该修复已列入 [2.1.6 未发布更新记录](../../CHANGELOG.md)。

**适用范围：**仅替换 `custom_backend/pdf_fetch_api.py`，不修改数据库、API Key、任务记录、前端或版本号。桌面打包程序需要重新构建，不能通过在可执行文件旁放置本补丁来更新。

**平台要求仍须满足：**服务器必须能够访问 AI 平台，Base URL、API 格式、模型权限与 API Key 必须匹配。此补丁不增加 OpenCode Go 的专用会话头，也不解决上游的 401、额度、模型权限或额外客户端要求；不能据此保证任意供应商或任意 Key 均可使用。

### Ubuntu / Linux 操作步骤

在**实际部署的 2.1.5 源码目录**操作，不需要切换整个分支或拉取其他维护改动。以下步骤逐项执行；任何校验失败都应停止，不要强行应用或忽略错误。示例使用 `.venv/bin/python`；请替换为后端实际使用的 Python。需要 `curl`、`git`、`sha256sum`。

1. 下载补丁到临时目录，并验证补丁及原始文件。

   ```bash
   cd /home/ubuntu/mubi-reviewflow
   patch_dir="$(mktemp -d)"
   curl --fail --location --show-error \
     'https://raw.githubusercontent.com/RUCbookshelf/mubi-reviewflow/379f8d7d7c5be9e20ded54e2174baa8cd08657da/patches/2.1.5/https-python312.patch' \
     --output "$patch_dir/https-python312.patch"
   printf '%s  %s\n' \
     'd5e048ec919327d58a702b8b23a53591b0ce9ebb18e8ef72df4ac8436509c831' \
     "$patch_dir/https-python312.patch" | sha256sum --check -
   printf '%s  %s\n' \
     '46fa63c47c2940a6aec425d1b280b38b66f0a56f7a6eb8daa015e4b1b17ff4c3' \
     'custom_backend/pdf_fetch_api.py' | sha256sum --check -
   git -c core.autocrlf=false -c core.eol=lf apply --check \
     "$patch_dir/https-python312.patch"
   ```

   将 `/home/ubuntu/mubi-reviewflow` 换成实际目录。若原始文件不匹配，可能已打过补丁、有本地改动或不是对应源码；先核对，不能覆盖本地改动。若当前文件已等于“打补丁后”的 SHA，则无需重复应用。

2. 备份原始文件，并记下备份路径。按日常运维流程保留数据备份。

   ```bash
   backup_dir="$HOME/reviewflow-backups/https-compat-$(date +%Y%m%d-%H%M%S)"
   mkdir -p "$backup_dir"
   chmod 700 "$backup_dir"
   cp -p custom_backend/pdf_fetch_api.py "$backup_dir/pdf_fetch_api.py"
   printf 'Backup: %s\n' "$backup_dir/pdf_fetch_api.py"
   ```

3. 停止后端，再应用补丁、核对结果并检查语法。在**同一终端**继续执行，以保留 `patch_dir`、`backup_dir`。下面的 `reviewflow.service` 是示例服务名，请替换为实际 systemd unit；使用 Docker 或其他进程管理器时按原部署方式停止并重建/重启，不要同时启动第二个后端。

   ```bash
   sudo systemctl stop reviewflow.service
   git -c core.autocrlf=false -c core.eol=lf apply \
     "$patch_dir/https-python312.patch"
   printf '%s  %s\n' \
     '5ca712384052ae24fb4b37b939985e5c6de7e6fbfe95d41cea760b4d0fd780ca' \
     'custom_backend/pdf_fetch_api.py' | sha256sum --check -
   PYTHONPYCACHEPREFIX="$patch_dir/pycache" \
     .venv/bin/python -m py_compile custom_backend/pdf_fetch_api.py
   ```

   校验和语法检查均成功后，再启动原服务：

   ```bash
   sudo systemctl start reviewflow.service
   sudo systemctl status reviewflow.service --no-pager
   ```

   若应用、校验或语法检查失败，先恢复下面的备份，再启动服务。不要把失败后的文件直接投入使用。

4. 在浏览器中验证：保存正确的平台配置，点击“测试连接”；随后到“导入核验 → 信息差异”生成一次 AI 建议，确认说明和字段标记显示正常。若返回平台的认证、模型或额度错误，应按该平台要求继续排查。生产环境保持原数据目录、服务器模式和反向代理配置。

### 回滚

停止后端，将备份文件恢复，再启动原服务：

```bash
sudo systemctl stop reviewflow.service
cp -p "$backup_dir/pdf_fetch_api.py" custom_backend/pdf_fetch_api.py
sudo systemctl start reviewflow.service
```

若重新打开了终端，请将 `backup_dir` 设为第 2 步记录的真实路径。回滚不涉及数据库或 API Key。

### 换行与验证说明

补丁和目标文件使用 LF。命令只为本次 `git apply` 固定换行设置，不修改全局配置；不要对整个仓库执行换行归一化。Windows 下载/传输后也应检查 SHA-256，避免编辑器自动改成 CRLF。

修复在 Python 3.12.13 的隔离环境完成 41 项回归及 15 个子测试，并经独立静态复核；有限 TLA+ 模型检查通过，旧缺陷及错误参数变异均能产生反例。真实浏览器经受控 HTTPS 上游验证了 Chat/Responses 建议、坏证书拒绝、错误降级及恢复，原题录和人工处理状态保持不变。这些结果验证兼容修复与业务链，不代表所有外部平台都已接入成功。

## English

### Scope

This is a **source-deployment hotfix for ReviewFlow 2.1.5**. On Python 3.12 and similar newer runtimes, the shared HTTPS connector accessed a removed standard-library attribute, causing a generic HTTP 500 before an AI request reached the provider. The patch preserves legacy argument handling and works with the newer interface without disabling TLS verification or address protections.

Only `custom_backend/pdf_fetch_api.py` changes. No database, credentials, task records, frontend files or version numbers change. Packaged desktop executables require a rebuild. The fix is listed under **2.1.6 — Unreleased** in [CHANGELOG.md](../../CHANGELOG.md).

This patch does not add OpenCode Go session headers or fix authentication, quotas, model permissions, network access or provider-specific client requirements. Successful controlled-upstream tests do not establish successful access to every provider.

### Applying to 2.1.5

Use the numbered Linux instructions above from your existing deployment directory. The commands download the [single-file patch](../../patches/2.1.5/https-python312.patch), verify the patch and original file, check applicability, back up the original, stop the backend, apply the patch, verify the resulting hash, compile-check with the deployment's Python, and start the original service. Replace the example deployment path, virtual environment and `reviewflow.service` unit name with your actual settings. Keep the same terminal open so the temporary and backup directory variables remain available. Check each command's result and stop on any failure.

Expected SHA-256 values:

- Patch: `d5e048ec919327d58a702b8b23a53591b0ce9ebb18e8ef72df4ac8436509c831`.
- Original file: `46fa63c47c2940a6aec425d1b280b38b66f0a56f7a6eb8daa015e4b1b17ff4c3`.
- Patched file: `5ca712384052ae24fb4b37b939985e5c6de7e6fbfe95d41cea760b4d0fd780ca`.

If the original hash differs, investigate before applying: the installation may already be patched, locally customized or based on different sources. Do not force the patch. Do not switch the entire deployment branch or import unrelated maintenance changes.

For rollback, stop the backend, restore `pdf_fetch_api.py` from the recorded backup directory, then start the same service. For Docker, rebuild/redeploy using the existing workflow; do not run a second backend alongside it. The per-command Git options keep LF line endings without changing global configuration or normalizing the repository.

Finally, use the browser to test the saved provider configuration and generate a real suggestion under **Import review → Information differences**. An upstream 401 or model/quota rejection still requires provider-specific troubleshooting.
