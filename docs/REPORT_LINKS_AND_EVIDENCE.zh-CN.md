# 报告关联与证据：使用引导

适用版本：2.1.4。

## 什么时候需要使用？

通常照常筛选、编码即可。发现不同文章可能报告同一研究、复用同一样本或存在部分重叠时，再记录关联。作者、题名或样本量相似只能提供线索。

报告关系与“同一篇文献的重复导入”不同。关联不会删除文章、复制筛选决定、转移编码，或自动改变效应量选择。

## 1. 记录个人线索

初筛和复筛工具栏提供“关联报告”；编码页面提供“报告关联与证据”。选择另一篇报告，标记关系并填写依据及位置。同一研究与相同样本分别判断。

线索按登录成员保存。保存成功才关闭表单；服务器拒绝或网络失败时保留输入。另一窗口已改变资料时会拒绝覆盖，需重新载入并核对。

## 2. 核对和裁决

“合并仲裁 → 报告关系裁决”提供个人线索与确认关系。个人任务的所有者可直接确认；团队任务须有所有者／仲裁者权限，并在首页暂停初筛、复筛和编码后开展裁决。独立阶段不展示其他成员的提议。

不确定的关系可以保留为线索；确认关系前必须补充依据。已确认关系可以提出修改，在裁决入口解除或撤销最近裁决。个人变更和共享裁决分别撤销；每个撤销只能恢复当前最近一次变更，后续保存会推进版本。

关系注释与现有统计研究 ID 归组分别保存。“查看研究归组”可打开已有研究与报告表单，核对统计分析和 PRISMA 所用研究单位。软件不会根据样本重叠自动改写原研究 ID。

## 3. 提取定性证据

编码页面打开“定性证据草稿”，分别填写作者发现、支持引文、页码、参与者与情境、主题和综述者解释。可为同一报告新增多条发现。JBI 路径可人工记录发现的可信度；缺乏支持的发现仍保留在原草稿中。

原编码维度、“保存本篇”、PDF 注释与高亮继续独立使用。证据草稿保存到服务器／本机任务数据中的个人工作区，不只存在浏览器缓存。

## 4. 使用综合工具

“分析 → 定性证据综合 → 综合工具”提供方法设置、工作区、证据矩阵、综合前核对和置信度评估。

- JBI：记录类别形成、综合发现及缺乏支持发现的处理依据。
- 主题综合：保留原文编码、描述性主题、分析性主题与推理。
- 框架综合：记录框架来源、证据映射和框架外发现。
- 元民族志：记录概念、互惠／反驳转译及论证链。
- 混合方法：分别形成定量、定性证据，再记录整合备忘。

这些是研究者使用的方法工作区；不会自动生成主题、论证链或综合结论。

## 5. 核对共同原始证据

综合前核对会提示不同报告中完全相同的非空引文。人工对照报告与页码，选择同一证据、不同证据或不确定。相同文字不自动证明共同出处。

确认同一证据后，矩阵合并展示出处；原报告、原草稿和互补发现保留。不同主题相似也不会触发删除。

## 6. 评价与置信度

现有偏倚风险页面增加 JBI／CASP 定性评价入口：十项中文释义、逐项判断、依据和位置，可保存未完成草稿。它不替换 RoB 2 等现有工具，不计算质量总分、不自动排除研究。

JBI 汇聚式综合使用 ConQual 工作区记录可靠性及可信度；其他定性路径提供 CERQual 的方法学局限、一致性、充分性和相关性。每条综合发现可单独新增评估，并记录总体置信度及依据。工具不自动降级，也不保证某种综合方法与评价体系天然适配；由协议和原始方法指南决定。

## 7. 导出与轨迹

矩阵中可下载个人证据表 CSV，含 DOI、期刊、作者及原始来源文件；JSON 工作资料还包含关系提议、方法备忘、问题、评价和置信度。JSON 是可审阅的资料导出，本版未增加工作区 JSON 导入。

新增操作记录到现有个人“轨迹”，遵循记录开启／暂停设置。大工作区的轨迹保存摘要与哈希，当前完整内容通过 JSON 导出检查。自 2.1.4 起，旧版整份工作区快照事件会在打开工作区或导出轨迹时一次性折叠为按保存批次的增量记录（见下节）：同批多主体自有事件合并时条数减少，导入事件按 origin 行保留、单主体保存链条数不变。

### 2.1.3 存量轨迹的一次性迁移与保留

2.1.3 及更早版本每次保存把整份工作区快照写入轨迹事件；累积后可能把轨迹导出推过 32MB 上限（导出返回 413），共享裁决轨迹中也可能留存其他成员的依据／位置原文。自 2.1.4 起：

- 系统在下一次打开报告关联工作区或导出轨迹时，自动把这些旧事件一次性压缩为与当前格式一致的按报告增量（体积超限时降级为摘要＋哈希），并按事件归属人脱敏非本人提案的依据与位置（依据仅保留哈希与长度；位置这类低熵文本直接丢弃，不留可枚举比对的哈希）。迁移幂等且带完成标记，只改写 2.1.3 全量快照事件（含导入行）的 before/after 载荷：同一保存批次的多主体自有事件合并为一条增量事件（条数相应减少；合并事件仅保留首个主体，其余主体记入载荷 `affected_subjects`），单主体保存链条数不变、仅压缩载荷；导入事件不合并不删除，origin 行与 origin_* 列原样保留（旧导出包重导入仍判定为重复导入），before/after 载荷同样逐行改写为增量或摘要；幸存事件的序号、时间、阶段、主体等元数据保持不变，四张幂等回执表不受影响；迁移前对涉及的数据库文件创建 `.pre-fold-v1.bak` 备份（已存在则不覆盖）。
- 公开（public）轨迹导出在导出侧一律脱敏、与迁移是否已执行或成功无关：关系条目中的依据（evidence）仅保留哈希与长度，位置（locator）这类低熵文本仅保留长度；证据草稿文本（发现、情境、主题、综述者解释与草稿位置）同样只留长度摘要。私有备注与来源引句默认按私有键移除；在公开导出界面显式勾选「包含私有备注／包含来源引句」时，对应文本按选择保留原文，其余关系／草稿字段仍兜底脱敏。事件内嵌的 origin 副本不再原样外带，而是经与事件本体相同的公开管线（含上述选择）结构化脱敏后保留，导入来源仍可追溯。完整备份（complete）导出不做导出侧脱敏，保持个人完整备份语义：本人内容与 origin 副本按库内存储原样导出；他人条目呈现为摘要的前提是写入时脱敏或迁移已成功执行——迁移未执行或失败（如备份失败、写锁超时）时，未折叠旧事件中的他人依据／位置原文会随 complete 包原样带出。
- 保留与清理指引：迁移只消除旧快照的体积与外带风险，不缩短记录时段（单主体保存链条数不变，同批多主体自有事件合并时条数减少，每个保存批次仍至少保留一条事件）。若仍需缩减轨迹（例如长期任务接近导出上限），可在“轨迹”页清除个人历史——清除只删除轨迹事件并重新建立基线，不影响已保存的报告关系、证据草稿或任何筛选／编码数据。
