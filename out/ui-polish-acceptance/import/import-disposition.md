## A-DYN-16 follow-up

Approved minimal change: keep authentication, theme, atlas, all pre-main scripts, `workflow_locale.js`, CSS and offline notice eager. Defer 123 workspace scripts in their original order until `/auth/me` succeeds. `enterApp` waits for workspace initialization before assigning `S.user` and dispatching task/page events. The loader waits for document parsing, shares concurrent entry attempts and resumes a failed network load without reexecuting successful modules. A generic localized login error allows retry.

The inert tags retain their exact `src` attributes and carry the boolean `data-rf-app` marker with an unrecognized script type. The loader reads that same `src` when activating each module, so the unmodified static manifest parser and runtime share one URL list. No build manifest parser or gate rule is changed.

After the compatibility change, the isolated Edge probe observed zero requests/executions for inert tags with `src`, then exactly one request/execution after activation. The full login suite again passed with 17 eager requests / 123 deferred scripts and zero page errors. The existing `build/script_manifest.cjs` parsed 143 modules (including the dynamic PDF modules), found the unique `unified_import_workspace.js` producer and passed its reverse-manifest rule. The unmodified `build/validate_import_review_static.cjs` passed with `syntax_files:143`, `inline_scripts:3`, and complete new-panel translation coverage.

`app_module_loader.test.cjs`: 4 passing behavioral tests cover no unsolicited loading, order, retry, concurrency and document-ready gating. `lazy_login_qa.py`: a fresh signed-out browser fetched 17 document scripts, with no workspace modules; theme and atlas worked. A controlled failure for `analysis_forest.js` kept the login page usable, retry completed with one execution of already loaded modules. Import deep-link login, stored-token reload, required module globals and zero page errors passed. Service workers were blocked for a consistent count of document script requests; this is not a claim about all PWA background network traffic. Evidence: `qa/lazy-result.json` and `qa/lazy-deeplink-import.png`.

GitNexus could not resolve `enterApp` in the available index (UNKNOWN), so source-order/event consumers were inspected directly. The only footer `window.load` bootstrap hook is in workflow controls and would return without a selected task during anonymous initialization; normal task-context and workspace-entry events still initialize it. The eager help locale retains its DOMContentLoaded listener; the eager offline module checks `readyState` itself. No backend, authentication semantics, or workspace script internals were changed for A16.
